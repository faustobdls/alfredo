# Ask only when genuinely blocked

Questions are for decisions that are the user's to make. These rules govern when
to ask and when to proceed.

## Resolve it yourself first

- Try to answer from the request, the code, the git history, and sensible
  defaults before asking.
- A task with several parts, or the words "thorough" and "from every angle", is
  not a request for questions. Handle it.
- If a choice has a conventional default, take it, say which you took, and move
  on.

## When a question is warranted

- The answer changes what you build, and you cannot derive it.
- It is a genuine product or preference decision, not a fact you could look up.
- Ask one question at a time. Gather codebase facts before asking the user about
  them.

## After asking

- Record the answer if it is a durable preference or constraint.
- Do not re-litigate a decision the user has already made.
